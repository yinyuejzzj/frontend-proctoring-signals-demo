# Frontend Proctoring Signals Demo

这是一个面向前端监考信号研究的演示型仓库，重点说明：在研究与教学场景中，常见的前端“监控绕过思路”主要体现在浏览器事件、页面状态、全屏状态与 iframe/SPA 动态环境的控制上。

## 技术路径

该项目主要展示以下几条技术路径：

1. 事件监听拦截
   - 重写 EventTarget.prototype.addEventListener 和 removeEventListener
   - 屏蔽 blur、focusout、visibilitychange、fullscreenchange 等关键监控事件
   - 让页面看起来持续处于正常状态，减少被监控系统捕获的异常信号

2. 可见性与焦点伪装
   - 修改 document.hidden、document.visibilityState、document.hasFocus 等状态
   - 让页面表现为始终可见、始终聚焦
   - 使监控系统难以识别窗口切换、后台运行、失焦等典型异常行为

3. 全屏状态控制
   - 拦截 requestFullscreen、exitFullscreen 等 API
   - 强制返回正常状态值，避免全屏切换被系统记录为异常

4. 复制/粘贴/右键等输入行为绕过
   - 通过监听和阻止关键输入事件，降低复制、粘贴、选择、右键等行为被监测到的概率

5. iframe 与 SPA 环境加固
   - 对 iframe 内部环境进行状态重写和事件拦截
   - 对动态页面变化使用 MutationObserver 持续维持“假正常”状态

## 使用效果

脚本加载后，主要体现为以下效果：

- 页面更容易保持“正常可见、正常聚焦、正常全屏”状态
- 失焦、切屏、隐藏、全屏切换等行为信号被降低或掩盖
- 对浏览器事件和状态读取的结果进行重写，影响前端监控系统的判定逻辑
- 在 SPA 和 iframe 场景中，动态页面切换不会很快破坏脚本的状态控制效果

这类内容适合用于：

- 分析前端监控系统依赖哪些信号
- 演示监控机制的脆弱点和边界
- 研究事件监听、状态伪装与浏览器 API 组合使用方式

## 可导入到脚本猴（Tampermonkey）

这个脚本样例符合 Tampermonkey 用户脚本格式，适合直接导入到脚本猴中使用。

使用方式：

1. 将脚本保存为 `.user.js` 文件，例如：`proctoring-study-demo.user.js`
2. 安装 Tampermonkey 浏览器扩展
3. 在脚本管理器中导入该脚本
4. 在目标页面中运行后，即可观察事件、状态和全屏信号被脚本控制的效果
